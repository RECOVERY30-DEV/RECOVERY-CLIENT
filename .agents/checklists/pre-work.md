# Pre-work Checklist

작업을 시작하기 전에 범위와 근거를 확인합니다.

## Required

- `docs/agent/working-agreement.md`와 `docs/rules/project.md`를 읽습니다.
- `git status --short --branch --untracked-files=all`로 현재 브랜치와 사용자 변경을 확인합니다.
- 새 작업 브랜치가 최신 `origin/develop`을 기준으로 만들어졌는지 확인합니다.
- 변경 대상 코드, 설정, 문서와 관련 기존 패턴을 먼저 찾습니다.
- 필요한 문서만 추가로 읽고 관련 없는 문서를 전부 로드하지 않습니다.
- 새 기능, 초기 설정, 아키텍처 작업은 승인된 설계 범위인지 확인합니다.
- commit, push, PR, merge가 요청 범위에 포함됐는지 각각 확인합니다.

## Stop And Clarify

- 결과나 공개 API가 크게 달라지는 선택이 필요합니다.
- 기존 코드와 문서가 충돌하고 어느 쪽이 맞는지 확인할 근거가 없습니다.
- 관련 없는 사용자 변경과 동일 파일을 수정해야 합니다.
- 비밀정보, 운영 환경, 외부 서비스 권한이 필요합니다.

질문이 필요하면 한 번에 하나만 하고, 안전하게 진행 가능한 조사는 계속합니다.
