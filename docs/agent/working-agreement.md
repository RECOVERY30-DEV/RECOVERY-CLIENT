# Working Agreement

사용자와 에이전트가 RECOVERY-CLIENT에서 협업할 때 따르는 기본 작업 계약입니다.

## 커뮤니케이션 선호

- 기본 응답 언어는 한국어입니다.
- 결론과 결과를 먼저 설명합니다.
- 어려운 개념은 구체적인 예시로 설명합니다.
- 과도한 헤더와 장황한 설명을 피합니다.
- 선택지가 있으면 추천안을 먼저 제시합니다.
- 확인하지 않은 내용을 완료처럼 말하지 않습니다.

## 작업 진행 방식

- 위험하지 않고 승인된 범위에서는 합리적으로 판단해 진행합니다.
- 결과가 크게 달라지는 경우에만 질문합니다.
- 질문이 필요하면 한 번에 하나씩 합니다.
- 기존 코드와 설정을 먼저 확인하고 현재 패턴을 따릅니다.
- 관련 없는 사용자 변경을 건드리지 않습니다.
- 새 기능, 초기 설정, 아키텍처처럼 결과 범위가 큰 작업은 구현 전에 채팅으로 설계를 제시하고 승인을 기다립니다.
- 별도 요청이 없으면 일회성 설계·계획 문서를 저장소에 만들지 않습니다.
- 새 production dependency, 외부 서비스 연결, 배포 또는 운영 환경 변경은 먼저 필요성과 영향을 설명합니다.
- 커밋, push, PR, merge는 각각 명시적으로 요청받았을 때만 수행합니다.

## 품질 기준

- 임시방편보다 원인을 해결합니다.
- 불필요한 추상화와 과도한 구조화를 피합니다.
- 파일과 모듈의 책임을 작게 유지합니다.
- 구현과 함께 변경 범위에 맞는 검증을 수행합니다.
- 최종 보고에 변경 내용, 검증 결과, 문서 영향, 남은 위험을 포함합니다.

## 자동화와 Skill 후보 제안

- 대화와 작업에서 반복 가능한 패턴이 보이면 에이전트가 먼저 자동화 후보를 제안합니다.
- 후보는 `rule`, `checklist`, `recipe`, `skill`, `script`, `hook`, `CI` 중 가장 작은 적합한 형태로 제안합니다.
- 원본 프롬프트나 전체 대화를 저장하지 않고, 검토 가능한 반복 패턴만 요약합니다.
- 사용자 승인 없이 skill, spec, 자동화 파일을 생성하지 않습니다.
- 후보 제안에는 발견한 패턴, 추천 형태, 실행 조건, 입력과 결과, 검증 방법을 포함합니다.
