# Commit Convention

변경 이유와 책임 단위를 이력에서 빠르게 이해하기 위한 commit 기준입니다.

## 기본 형식

```text
type: 한글 작업 내용
```

- type은 영문 소문자로 작성합니다.
- 제목은 한글로 변경 결과를 구체적으로 설명합니다.
- 제목 끝에 마침표를 붙이지 않습니다.
- ticket 번호와 상세 설명을 제목에 모두 넣지 않습니다.
- scope 표기는 도메인 구조가 안정되기 전까지 사용하지 않습니다.

## Type

| type | 사용 시점 |
| --- | --- |
| `feat` | 사용자에게 보이는 기능 추가 |
| `fix` | 잘못된 동작이나 회귀 수정 |
| `refactor` | 동작 변경 없는 코드 구조 개선 |
| `style` | UI와 CSS 변경 |
| `test` | 테스트 추가와 수정 |
| `docs` | 문서만 변경 |
| `chore` | 일반 설정과 유지보수 |
| `build` | dependency와 build 설정 변경 |
| `ci` | CI/CD workflow 변경 |
| `revert` | 이전 commit 되돌리기 |

## Commit 단위

- 한 commit에는 하나의 논리적 책임만 포함합니다.
- 문서, 구현, 자동화처럼 독립적으로 설명 가능한 변경은 가능한 한 분리합니다.
- 각 commit은 해당 시점의 저장소에서 이해 가능하고 검증 가능한 상태를 유지합니다.
- 관련 없는 파일을 함께 stage하지 않습니다.
- `수정`, `작업`, `WIP`처럼 내용을 알 수 없는 제목을 사용하지 않습니다.

## 본문

제목만으로 이유와 영향을 설명하기 어려울 때 본문을 추가합니다.

- 무엇을 바꿨는지보다 왜 바꿨는지 설명합니다.
- 중요한 선택지와 제외 범위를 기록합니다.
- migration이나 후속 작업이 필요하면 명시합니다.

## 예시

```text
feat: 회복 기록 목록 조회 기능 추가
fix: 빈 회복 기록 제출 오류 수정
docs: 코드 및 협업 컨벤션 정리
chore: 에이전트 하네스 자동 검증 구성
ci: develop PR 검증 workflow 추가
```

commit, amend, rebase, push는 사용자가 각각 명시적으로 요청한 범위에서만 수행합니다.
