# Project Rules

모든 작업에서 반드시 확인하는 RECOVERY-CLIENT의 핵심 불변 규칙입니다.

## 도구와 저장소

- 패키지 설치와 script 실행에는 `pnpm`만 사용합니다.
- 실제 설치 상태는 `package.json`과 `pnpm-lock.yaml`을 기준으로 판단합니다.
- 새 작업은 `develop`을 기준으로 시작하고 기능 PR은 `develop`을 대상으로 합니다.
- `main`은 `develop`에서 배포 가능한 상태를 승격할 때만 사용합니다.

## 변경 안전성

- 관련 없는 사용자 변경을 수정, 삭제, stage하지 않습니다.
- 비밀정보, token, 실제 운영 환경값을 코드, 문서, 로그에 남기지 않습니다.
- 사용자 승인 없이 배포, 운영 환경 변경, 외부 서비스 변경을 수행하지 않습니다.
- 사용자 요청 없이 commit, push, PR, merge를 수행하지 않습니다.
- 파괴적인 Git 명령, force push, 광범위한 재귀 삭제를 사용하지 않습니다.

## 구현 원칙

- 현재 코드와 설정을 먼저 확인하고 존재하지 않는 구조를 추측하지 않습니다.
- 임시방편보다 원인을 해결합니다.
- 파일과 모듈은 하나의 명확한 책임을 갖게 합니다.
- 실제 재사용이 확인되기 전에는 공용 추상화로 승격하지 않습니다.
- 새 라이브러리보다 현재 도구와 플랫폼 기본 기능으로 해결 가능한지 먼저 확인합니다.
- 안정적인 API와 널리 사용되는 단순한 기술을 우선합니다.

## 문서와 검증

- 설치되지 않은 도구나 예정된 구조를 현재 상태처럼 문서화하지 않습니다.
- 코드, 설정, 의존성, 명령, 폴더 구조가 바뀌면 문서 영향을 확인합니다.
- 변경 범위에 맞는 검증을 직접 실행하고 결과를 보고합니다.
- 실행하지 않은 검증과 확인하지 않은 동작을 완료로 표현하지 않습니다.
